--------------------------------------------------------------------------------
PRE-PROMPTING / SETUP
--------------------------------------------------------------------------------

Before using Cursor, I built the initial version of the app:

  - Implemented the core flow in vanilla JavaScript using getElementById to
    read user input, call the MealDB API, and update the DOM with results.
  - Used basic HTML: a search input, submit button, and a results container
    with a list for meal names and images.

Planning advice (ChatGPT):
  I asked ChatGPT for the best way to hide and show elements when switching
  between the search screen and the results screen. The recommendation was to
  use a CSS class (e.g. .hidden { display: none; }) and add/remove that class
  in JavaScript instead of manipulating styles directly.

State when I started using Cursor:
  The app could search and display meal data from the API, but it had no
  styling, no clear direction for how to improve the UI, and no way to return
  to search after viewing results (e.g. a "Search again" or back button).
  I decided to use Cursor from this point to implement the "vibe coding"
  portion—specifying what I wanted and letting the AI handle implementation.

--------------------------------------------------------------------------------
PROMPTS (Cursor)
--------------------------------------------------------------------------------

1. Styling — search and results
   "can we style the app so that it looks nice when the user enters their food
   and then also when the results pop up lets style that so it looks nice in
   multiple cards"

   AI RESPONSE SUMMARY:
   - Styled the whole app: dark gradient background, DM Sans font, centered
     search section with title, tagline, and a polished input + gold Search
     button.
   - Rendered results as a responsive grid of cards (image + meal name per
     card) with hover effects and a "Search again" button in the results
     header.
   - Updated HTML structure (form, results header, results-grid div, no-results
     message) and JS to build meal cards in the grid and handle empty/error
     states.

   WHAT I LEARNED:
   - Planning UI in components/sections first helps styling decisions become
     more consistent.
   - Design quality depends on font hierarchy, color contrast, and spacing
     rhythm (for example 8/16/24 px spacing scales).
   - classList.add() / classList.remove() is a clean way to toggle UI states
     without directly changing inline styles.

   ISSUES ENCOUNTERED:
   - After clicking "Search again" and searching a second time, the button
     disappeared.

   HOW I FIXED IT:
   - Re-prompted with a focused bug description and updated DOM rendering logic
     so content is injected into the results grid only.

2. Bug — "Search again" button missing on second results view
   "why when i search and get to results then when i search again the button
   isnt there the second time that says search again"

   AI RESPONSE SUMMARY:
   - Found that showSearch() was clearing the entire results container with
     innerHTML = "", which removed the "Search again" button from the DOM.
   - Fixed by having showSearch() only clear the results grid and the
     no-results message, and having searchRecipes() write only to the
     results-grid div so the header (and button) always stay in the DOM.

   WHAT I LEARNED:
   - Updating a parent element with innerHTML can accidentally remove nested
     controls and event wiring.
   - It is safer to keep static layout elements in place and only clear/update
     dynamic content containers.

   ISSUES ENCOUNTERED:
   - I initially did not realize that clearing the whole results container
     removed the button itself.

   HOW I FIXED IT:
   - Changed showSearch() to clear only the results-grid and no-results state.
   - Kept the results header persistent in HTML so "Search again" always stays
     available.

3. Re-apply changes
   "I rejected the changes before but this time i want to accept"

   AI RESPONSE SUMMARY:
   - Re-applied the full CSS (search + results styling, card grid) and the
     updated JS (cards in results grid, showSearch only clearing the grid)
     so the "Search again" button would persist and the UI would match the
     previously offered design.

   WHAT I LEARNED:
   - If I reject an edit by mistake, I can ask Cursor to re-apply the same
     changes quickly.
   - Keeping structure in HTML and logic in JS makes re-application cleaner.

   ISSUES ENCOUNTERED:
   - Changes were accidentally rejected, so the app reverted to an older state.

   HOW I FIXED IT:
   - Requested re-application explicitly and verified that both CSS and JS were
     restored.

5. Specifications document implementation

"I will go over the leftover features that need to be implemented. 

When a user searches and we fetch from the API there should be a loading spinner indicating we are waiting for results

Currently after we search we display the results with an image and a title in a card like component. This is good but we need to modify this a bit.
We want to also add category to our display and also a feature where when we click the card then it gives us more details of the meal. 
This includes the previous information as well as Ingredients, Instructions, and a Youtube Video Link. "

AI RESPONSE SUMMARY:
   - Implemented the remaining features from Specifications.txt:
     - Added a loading spinner while API results are being fetched.
     - Added category text to each meal card.
     - Added clickable cards that open a detailed meal modal.
   - The modal now shows:
     - title
     - image
     - category
     - ingredients list
     - instructions
     - YouTube link (only when available)
   - Added keyboard support to close the modal with the Escape key.

   WHAT I LEARNED:
   - A detailed spec gives AI clear implementation targets and better output.
   - Breaking a feature into UI, behavior, and data mapping steps makes it
     easier to build and debug.

   ISSUES ENCOUNTERED:
   - In detailed view, the image looked cropped and did not show the full meal
     image as expected.

   HOW I FIXED IT:
   - Updated modal image CSS to use object-fit: contain with a max height so
     the full image is visible.
   - Tested alternate styling and reverted to the preferred version.
